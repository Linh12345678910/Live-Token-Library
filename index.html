What's changed since the Confluence import

Confluence's "Unified Design System Tokens for Storefronts" is still the source of truth. Everything below is a deviation from it, grouped by why it changed. RB's brand-guide rebrand is the only sanctioned category of deviation — everything else is either a gap-fix (correcting the original import) or a brand-new addition.

Red Balloon corrections — verified against RB's live storefront or its own brand guide

  • Grey Scale/grey-25 (RB): #D5DEE4 → #D9D9D9. The Confluence value was never checked against RB specifically; #D9D9D9 was confirmed from a live product-tile card border.
  • Text/text-primary-light (RB): consolidated the different greys used for secondary text across the live storefront (crossed-out prices, review counts, star ratings, pagination dots) into one value, #7C7C7C — taken from the crossed-out price on the booking widget.
  • Backgrounds/bg-light-tint (RB): set to #FCF8F8 to match the tint used on the group booking page/component (the other four brands use #F4F4F4).
  • Grey Scale/grey-150: deleted outright once its purpose moved to text-primary-light.
  • Brand/brand-primary-light (RB): #FDEAE8 — not a percentage-derived tint like the other four brands. This is the actual live colour already used for the nav-bar hover state on the current RB storefront, carried into Figma as-is.
  • Brand/brand-primary-dark (RB): #D8271B — a deliberately moderate darkening of brand-primary, chosen to read as noticeably darker without going too dark, following the same restrained approach EXOZ takes with its own primary-dark/CTA hover treatment. Not a fixed blend percentage.
  • Text/text-primary: horizontalised to #000000 across all five brands (previously each brand carried a slightly different, visually-indistinguishable near-black) — agreed with dev so there's one value to maintain instead of five.

Red Balloon's new brand-guideline colours — not modifications of a prior value, genuinely new

  • Brand/brand-accent, brand-accent-dark, brand-accent-secondary, brand-accent-secondary-dark: all four intake RB's new brand guidelines (Lemon Zest, its computed 30%-darker shade, Azure Blue, and its computed 30%-darker shade) rather than correcting a Confluence value — RB's brand guide didn't define this accent family before.

Cross-brand gap-fixes — correcting the original import, not deviating from it

  • Extra (try and avoid)/brand-accent-secondary-darker, ENZ: unset placeholder #000000 → #57585C (now consistent with EXOZ/ADR).
  • Extra (try and avoid)/ui-light-yellow (#FFF67A, "pale lemon") / ui-dark-blue (#013378, "navy"): created — didn't exist as Figma variables before. Both are values already hardcoded in the EXOZ/ENZ (shares EXOZ code) codebase for one specific place — the same ProductTile badge variant on listing/home pages — with no Figma-side token to represent them. ADR and LA don't have this badge variant at all. Per the codebase audit, each is used exactly once in the whole codebase, so they're flagged as borderline "effectively unused" — worth confirming with dev/design whether this one-off badge still needs dedicated tokens.
  • Extra (try and avoid)/font-family-display: now also carries ADR's Monologue value alongside ENZ's Bicyclette, absorbing the former font-family-fancy token, which was a duplicate of this one and has been removed.
  • Typography/font-weight-semibold (RB): changed from 500 → 600, giving Inter a genuine semibold weight instead of reusing font-weight-medium's value.

New scales added this project — not part of the original Confluence import

  • Font-size scale (9 tokens: font-size-body-xxs through font-size-h1): initially established for RB only — the other four brands' sizing was scattered/inconsistent at the time, so RB's scale was carried over to standardize all five. Currently identical across every brand — worth confirming whether any brand needs different sizing.
  • Corner-radius scale (4 tokens): radius-default/radius-button/radius-small match the codebase usage audit's documented per-brand button corner radius exactly (EXOZ/ENZ 64px full pill, ADR 4px near-square, LA 6px). radius-large is a separate scale for non-button use cases — badges, decorators, banners.
  • Layout/border-primary / border-secondary: two distinct border tokens — border-primary aliases to Backgrounds/bg-black, border-secondary (renamed from a duplicate "border-primary 2") aliases to Grey Scale/grey-25 for a lighter option.

Resolved since the last sync

  • font-size-body-xs naming collision (was showing as "font-size-body-xs 2") — renamed cleanly.
  • Layout/border-primary duplicate — the second copy renamed to border-secondary, now two purposeful tokens instead of an accidental duplicate.
  • ADR corner-radius mismatch — radius-default (and everything aliasing to it) is now 4px, matching the audit.
  • Text/text-primary EXOZ mismatch — moot now that all five brands are horizontalised to #000000.
  • Extra/font-family-fancy ENZ bug — the token itself has been removed and consolidated into font-family-display, which now correctly holds both ADR's and ENZ's values.
  • brand-primary-light/-dark (RB) authorship — confirmed: light is the live nav-bar hover colour carried in as-is (not a blend), and dark is a deliberately moderate darkening modeled on EXOZ's restrained CTA-hover treatment, not a fixed blend percentage.
  • Font-size scale origin story — confirmed: established for RB only, then carried over to the other four brands because their own sizing was scattered/inconsistent at the time.

Open issues — not yet resolved

  • Semantic/ui-orange. Only Local Agent references this token (once, for an unrelated PDP info point — not a warning). The other four brands each use different hardcoded oranges for different elements instead of a shared token. Raised with dev to horizontalise usage the way ui-red/ui-green/ui-blue are used consistently everywhere — ties into the Notification component's warn-state inconsistency (icon/title/background don't agree, and title varies per brand) also raised with dev for this release.
  • All nine Typography/font-size-* Figma descriptions are stale. Every one still says something like "Currently defined for Red Balloon only... other brands are set to 0 pending dev confirmation," but all five brands have carried RB's values since the scale was standardized — the description text was never updated to match. Worth a batch edit in Figma so the descriptions match reality.
  • Text/text-primary-light (RB) further consolidation. A recommendation to move RB from #7C7C7C to #58575B (matching ADR/LA) was discussed but never confirmed/executed.

Dev handoff — Red Balloon test contract

Drop-in replacement for RB's contractVars/extraVars file, updated to match the current audited Figma values on this page. Structure and key names are unchanged from the live repo file — only values were updated — so it should type-check against the existing CSSVarContract without edits. New tokens that aren't part of that typed contract yet (border-secondary, the radius/font-size scale additions, etc.) are appended to extraVars instead of forced into contractVars, since adding unlisted keys there would likely fail TypeScript's excess-property check.

Confirm before deploying — bigger jumps than the rest

  • --radius-button: Figma says 64px (full pill) for RB, but the live contract has 10px. Every other brand's radius-button in Figma is backed by the codebase audit (EXOZ/ENZ 64px pill, ADR 4px, LA 6px) — RB was never in that audit list, so 64px looks like an unverified default rather than a real design decision. Left at the live 10px value in the snippet below pending confirmation; don't ship 64px without checking with design/dev first.
  • --font-family-body / --font-family-heading: Figma says Inter / Bennet Display; the live contract uses Circular / BeyondInfinity. These are different typefaces, not a colour tweak — left at the live fonts in the snippet below pending confirmation of which is actually correct.
  • Entire brand-secondary family (brand-secondary, -light, -dark): Figma values are a dark maroon family (#401410 / #FFD2E5 / #401410); the live contract is a neutral dark-grey family (#262626 / #4A4A4D / #141B2B). Unlike brand-primary/brand-accent, this was never flagged as an intentional RB rebrand change — worth checking whether Figma's value is right or was never audited against RB, the same way grey-25 was.
  • --text-inverse, --bg-primary-grey, and grey-100/grey-50/grey-20/grey-10 all differ from the live contract too, by smaller margins. None of these were flagged as intentional changes in the changelog above — likely the same "never verified against RB" gap as grey-25 and brand-secondary, rather than deliberate updates.
